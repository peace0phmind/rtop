# 三层差分保证与证据保鲜

状态：accepted。

## 已确认的挑战与默认决策

| 挑战 | 风险 | 默认决策 |
| --- | --- | --- |
| 分母漂移 | 新扫描结果或 fixture 改动悄悄缩小“100%” | 功能分母、fixture、Ontop 提交、容器 digest 与规范化器均版本化；任一变化触发证据保鲜。 |
| 双锚不一致 | Ontop 源码基线与使用方镜像结论不同 | 对每项记录两个锚；不一致阻止关闭，必须以差异裁决显式处理。 |
| 单边预期 | rtop 只符合自身硬编码答案 | 核心证据必须实际运行 Ontop 与 rtop，使用相同 PostgreSQL fixture 进行差分。 |
| 非确定结果 | 时间、随机值、blank node、SQL 未排序结果造成假差异 | 规范化器明确处理 blank-node 同构、bag、多重性、时钟/随机种子和显式顺序；无法规范化的行为必须冻结输入或列为环境不确定性。 |
| 覆盖率虚高 | 测试经过代码但未断言语义，或覆盖来自非矩阵测试 | 覆盖率报告按矩阵测试 ID 归因；排除行须显式列出理由。行/分支阈值仍是辅助门槛，不能替代差分。 |
| 资源行为不可比 | 只比较结果，遗漏取消、超时、下推退化 | 对 Ontop 已有资源契约的功能原子记录完成性、取消和资源阈值；阈值比较防退化，而不承诺相同 SQL、计划或绝对性能。 |
| 缺口被文档掩盖 | ledger、审计与 Issue 给出矛盾结论 | 闭合矩阵为唯一完成状态源；历史审计只可链接到矩阵，不能独立宣布完成。 |
| 测试共同缺陷 | Ontop 和 rtop 都因同一简化 fixture 通过 | 对高风险语义补充负向、变异和生成式案例；这些用于发现漏项，发现后必须进入固定矩阵原子。 |

## 关闭规则

“三个层已 100% 迁移”只在以下条件同时满足时成立：

1. 分母扫描可重放，且没有未分类功能原子；
2. 每个原子都具有通过的双边差分证据或有依据的 Ontop ignore/范围外裁决；
3. 每个原子链接到 rtop 实现位置、测试 ID、Issue、provenance 与覆盖率归因；
4. 层代码覆盖率满足 ADR-0005 的门槛，且不存在未解释的排除行；
5. 所有变更均通过证据保鲜，没有未裁决的功能漂移。

因此，单独的资产计数、SQL oracle、rtop 单边 regression、静态代码审阅或总覆盖率都不足以关闭 #35、#53 及其父 Issue。
